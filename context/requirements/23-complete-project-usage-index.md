# Complete available project-usage index

**Statement:** Projects indexes all available history from supported local Claude Code and Codex logs rather than silently limiting totals to the newest files or a scan prefix. Keep a private metadata-only local SQLite index at `Application Support/DynamicIsland/ProjectUsage/index.sqlite`, separate from `Application Support/DynamicIsland/usage.sqlite`; do not migrate, merge, or backfill CLIProxyAPI usage. Store only source file identity/stat metadata, source/session/response identities, timestamps, cwd, normalized counters/context needed for deduplication and attribution, and committed newline offsets with prefix-verification metadata. Apply private directory/database/WAL permissions (0700 directory, 0600 files). Do not retain raw JSON, partial rows, prompts, conversation/tool text, credentials, or other session content.

Bound each discovery, hash/verification, parse, maintenance, and publication pass; checkpoint and resume unfinished work across passes and app restarts instead of imposing a permanent total file/byte prefix quota. Stream JSON selectively so large valid non-usage content does not require retaining a full line or prevent later usage fields from being found; do not discard an otherwise valid event solely because its JSONL line exceeds the former 256 KiB cap. Progress must distinguish discovery, indexing, verification, and publication. Until catch-up and required validation finish, report partial progress/totals honestly; do not label the project list complete. On first catch-up, use finite captured watermarks so ongoing appends cannot starve existing history. This is not an atomic snapshot guarantee for a file actively changing during a scan.

Cache only source files still present. Reconcile changed, truncated, replaced, and removed files so confirmed removals retire their usage contributions; available history is not counter-pruned. Deleted logs and usage from unknown or unsupported sources cannot be reconstructed. History ranges are limited to retained local logs. Warm launches should reuse verified cached results and resume pending work. Revisit an unfinished physical row from its last committed newline; never persist the raw row as a checkpoint.

Use the supported producer shapes defined in [22](22-project-usage.md): count canonical Codex `token_usage_record` once per `(session_id, response_id)`; never count cumulative turn/thread fields or legacy `event_msg` `token_count` snapshots/deltas. Ignore legacy mirrors when canonical records exist; after a complete file has been examined with no canonical records, report legacy-only Codex usage as unsupported. Unsupported historical formats, malformed lines, unreadable sources, and invalid records may leave real gaps and must remain explicitly warned; do not claim every historical producer or local corpus was validated. Existing source choices, ranges, attribution, privacy, token arithmetic, and separation from proxy usage in 22 remain in force.

Project totals are across all indexed matching projects, not just the current visible page. Rank projects by usage and show at most 20 per page with Previous / Next navigation. Totals and attribution can change as indexing catches up or source files change; show that state rather than presenting a partial page as the complete ranking.

**Source:** User request, 2026-10-09.

**Verification (2026-10-10):** A full catch-up of currently supported records from the current retained local corpus reached ready using a read-only private temporary cache. Reopening the captured index preserved totals without reparsing already indexed rows; a later warm pass processed new/changed inputs without rereading the whole corpus. This did not use the production Application Support cache and does not certify every historical producer format. Conflicting, unsupported, and future-dated source records can legitimately warn; those are source-data/format warnings, not artificial file, byte, or line quotas. No personal counts, paths, or session data are recorded here.

**Status:** Current. Partly supersedes [22](22-project-usage.md)'s no-database/re-scan-after-restart and fixed source file/byte/record/resident scan-cap clauses; its source scope, filters/ranges, local attribution, counter semantics, privacy limits, and distinction from proxy usage remain current. Extends [18](18-page-toggles.md)'s Projects page.

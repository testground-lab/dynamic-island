# Local project usage

**Statement:** Add a third **Projects** page with source choices **All**, **Claude Code**, and **Codex**, and ranges **Today / 7d / 30d / 6m**. Show input, output, cache-read, cache-creation tokens and responses, with projects ranked by usage and neutral meters. Do not add pricing estimates or charts. If page toggles are offered, keep at least one page enabled.

Read local session metadata read-only from JSONL files under `~/.claude/projects/` and `~/.codex/sessions/` (Codex rollout logs); no management key is needed. Attribute by the session's absolute cwd. Missing or ambiguous cwd is **Unattributed**; worktrees remain separate projects. This is only the retained local log history available on this machine. It is not CLIProxyAPI queue attribution, must not be merged into proxy usage totals, and does not cover proxy requests that have no matching local session log.

Count only recognized token events, using their outer timestamp for the selected range. For Claude Code, deduplicate assistant usage by session and `message.id`, retaining the latest usage row for that ID; normalized input is `input_tokens + cache_read_input_tokens + cache_creation_input_tokens`. For Codex, prefer canonical `token_usage_record` events and count `payload.usage` once per `(session_id, response_id)`; `turn_token_usage` and `thread_token_usage` are cumulative and must not be summed. Codex `input_tokens` already includes cached and cache-write input, so do not add `cached_input_tokens` or `cache_write_input_tokens` to it. Normalized total is normalized input plus output. Show cache-read/cache-creation totals separately as subsets, not additional tokens to add again to input or total; reasoning is included in output, not an extra token category to sum. When canonical Codex events exist, ignore legacy `event_msg` `token_count` events without warning. If legacy `token_count` is the only Codex token source, report the format as unsupported rather than infer deltas from cumulative `total_token_usage`.

The original scanner re-streams changed files and reuses normalized in-memory results for unchanged files; it has no incremental-offset framework. Its fixed source caps and no-database/re-scan-after-restart policy are superseded by [23](23-complete-project-usage-index.md): bounded passes now checkpoint/resume in a private metadata-only index, and completeness must not be claimed before catch-up and verification. Malformed, unreadable, unsupported, or invalid data must remain explicitly reported. Never retain, store, or log prompts, conversation text, tool content, or other session content.
